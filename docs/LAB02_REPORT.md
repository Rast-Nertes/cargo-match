## Контрольные вопросы

### 1. Query, Path и Request Body — когда что использовать?

- **Query** (`?status=published&limit=10`) — необязательные параметры фильтрации, сортировки и пагинации; не идентифицируют ресурс, а уточняют выборку.
- **Path** (`/cargo-requests/{request_id}`) — обязательный идентификатор ресурса в иерархии URI; часть адреса, по которому клиент однозначно указывает объект.
- **Request Body** — полезная нагрузка при **POST/PATCH/PUT** (создание или изменение сущности); не используется для идempotent GET/DELETE.

**Правило:** идентификатор ресурса → path; модификация/создание данных → body; фильтры списка → query.

### 2. Идемпотентность HTTP-методов

**Идемпотентность** — повторный одинаковый запрос не меняет состояние системы сильнее, чем первый.

- **GET** — только чтение, состояние не меняется → идемпотентен.
- **PUT** — заменяет ресурс целиком; повтор с тем же телом даёт тот же результат → идемпотентен.
- **DELETE** — повторное удаление уже удалённого ресурса не создаёт «лишних» объектов (обычно 404) → считается идемпотентным по эффекту на домен.
- **POST** — каждый вызов **создаёт новый** ресурс (новая заявка, новый match) → **не идемпотентен**.

### 3. 401 Unauthorized vs 403 Forbidden

- **401** — клиент **не доказал личность**: нет заголовка `Authorization`, просрочен или неверный JWT. Нужно войти заново.
- **403** — клиент **аутентифицирован**, но **не имеет прав** на операцию (например, shipper пытается создать рейс перевозчика, или заблокированный `is_active=false` пользователь).

### 4. Зачем `components/schemas` и `$ref` в OpenAPI?

- **`components/schemas`** — единый каталог моделей данных (DTO), чтобы не дублировать описание полей в каждом эндпоинте.
- **`$ref`** — ссылка на общую схему (UserResponse, ErrorResponse); при изменении структуры правка делается в одном месте, контракт остаётся согласованным между paths.

### 5. PUT vs PATCH

- **PUT** — **полная** замена ресурса: клиент передаёт полное представление; отсутствующие поля могут трактоваться как сброс/null (зависит от API).
- **PATCH** — **частичное** обновление: передаются только изменяемые поля (например, только `status` или `free_capacity_kg` у рейса).

В CargoMatch для заявок и рейсов используется **PATCH**, что соответствует сценариям смены статуса без повторной отправки всей сущности.
